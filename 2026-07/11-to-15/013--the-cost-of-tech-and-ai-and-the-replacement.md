## Why This Works (And Where it Chokes)

### The Massive Wins
1. **The Backup Paradox:** In a database model, backing up a 10 GB database daily over 3 months creates **terabytes of redundant binary blobs**. Under your Git paradigm, because text files compress exceptionally well ($20-30\%$ of original size) and Git only records the exact text *diffs*, 3 months of rolling backups shrink from **terabytes to mere gigabytes**.
2. **The "No DevOps" Dividend:** Companies spend millions managing CI/CD pipelines just to compile JavaScript and ship it to a server. Running a simple Git hook delta deploy directly on a release box eliminates continuous integration server costs and energy.

### The Architectural Trade-offs
While this minimalist tech stack is perfect for $90\%$ of standard informational, informational-transactional, and operational web platforms, it faces scaling challenges in two main areas:
* **High-Concurrency Real-Time State:** For things like live seat-booking engines or global financial high-frequency trading, flat-file structures risk *race conditions* (two people writing to the same TSV simultaneously). 
* **Massive Scale Auditing:** If an operation does millions of transactions a day, git text diffs will eventually become too large for a standard release machine to index comfortably in RAM.
